1 Overview & Key Characteristics

Microcontroller Pins & Open-Drain Drivers

The I²C (Inter-Integrated Circuit) interface allows microcontrollers to communicate with peripheral devices using two designated pins: RC3/SCL (Serial Clock) and RC4/SDA (Serial Data).

When I²C mode is enabled, these pins operate as Open-Drain outputs. Pull-up resistors to $V_{DD}$ ensure that when the bus is idle, both lines default to a HIGH logic state.

Microcontroller Hardware Interface:
  • RC3 / SCL: Clock signal generated by Master to lock and shift data bits.
  • RC4 / SDA: Bi-directional serial data line pulled down by Master or Slave.

7-Bit Addressing + R/W Bit

The LSB of the first address byte ($R/\overline{W}$) dictates whether the master will Write (0) or Read (1) from the slave device.

Repeated START (Sr)

Allows switching from register selection (Write mode) to receiving register data (Read mode) without losing control of the bus.

Master ACK & NACK

During a Read operation, the Master sends ACK to request the next byte, and sends a NACK (NO ACK) after the final byte to terminate transfer.

Auto-Increment Registers

Subsequent data bytes automatically write or read sequential slave memory registers ($N, N+1, N+2$).

2 Hardware & Bus Topology

Interactive Circuit Schematic

Open-drain configuration with Pull-up Resistors ($R_P$) to $V_{DD}$

Open-Drain Architecture: Devices can only actively pull lines LOW (to Ground). When no device is pulling down, the pull-up resistors passively pull SDA & SCL HIGH ($V_{DD}$).

Bus Idle State (A)

When the bus is not occupied (idle), both SDA and SCL remain constantly in a HIGH level state.

Why Pull-up Resistors?

Since I²C drivers are open-collector/open-drain, two chips pulling the line in opposite directions (one HIGH, one LOW) will never cause a direct power short-circuit. Instead, LOW always overrides HIGH safely.

Rule 1 of I²C Communication:

A data transfer can only be initiated if the bus is completely idle (both lines HIGH).

3 Protocol Rules & Bus Conditions

Condition (B)

START Condition

A HIGH to LOW transition on the SDA line while SCL remains HIGH.

SCL: HIGH (1)
SDA: 1 ➔ 0 (Transition)
Bus becomes "BUSY" after START.
Condition (D)

Data Validity

SDA state must remain stable while SCL is HIGH. SDA may change state only when SCL is LOW.

SCL HIGH: SDA Sampled
SCL LOW: SDA Allowed to Switch
1 Clock Pulse = 1 Bit Transmitted
Condition (C)

STOP Condition

A LOW to HIGH transition on the SDA line while SCL remains HIGH.

SCL: HIGH (1)
SDA: 0 ➔ 1 (Transition)
Releases bus back to IDLE.

Byte Format & ACK Pulse

  • MSB First: Data is always transferred in groups of 8 bits (1 byte), starting with the Most Significant Bit (MSB). No byte limit per transfer.
  • Address Frame (Byte 1): Contains 7-bit Slave Address + 1-bit R/W flag (0 = Write to Slave, 1 = Read from Slave).
  • 9th Clock Acknowledge (ACK): For every 8 bits transferred, the receiving device must generate an ACK bit on the 9th SCL pulse by pulling SDA LOW.
  • NACK (Not Acknowledge): If SDA remains HIGH during the 9th pulse, it indicates a NACK (e.g. device busy, address not found, or master signaling end of read).
Standard 1-Byte Frame Sequence:
S Bit 7 (MSB) ... Bit 0 (LSB/RW) ACK (Bit 9) P

Clock Stretching Mechanism

If a slave device receives a byte but needs extra time to process data or perform internal operations (e.g., writing to EEPROM or running an ADC conversion) before receiving/sending the next byte, it can hold the bus.

How Clock Stretching Works:

The slave device actively holds the SCL line LOW. Since the clock line is open-drain, the Master is forced into a wait state until the slave releases SCL back to HIGH.

  • Prevents buffer overflow in slow peripherals.
  • Fully hardware synchronized without requiring extra dedicated interrupts.
